# upex

Jenny's CLI for named shortcuts to folders, apps, command lines and URLs. Data: `~/.upex/links.json` + `config.json`. Source: `E:\Downloads\Projects\Assets\upex`. If `upex` is not on PATH, use `node E:/Downloads/Projects/Assets/upex/bin/upex.js`.

## Rules

- Never run bare `upex` (interactive selector, takes over stdin and by default the whole terminal with mouse support: click a row to select, click it again or double-click to open, click tabs / openers / settings options, wheel moves the selection; Settings > Full screen Off draws it inline without mouse; Settings > Key hints Short/Off shrinks the key rows to one row or none (`upex config set keyHints short`); Settings > Glyphs ASCII (`upex config set glyphs ascii`) draws the selector with plain ASCII (< > | - . ^ v *) for fonts that show boxes; Esc clears a typed filter, then the marks, then closes a Shift+→ detail pane, then quits; Space marks (again: unmarks) the highlighted row (Shortcuts/Apps, ● in the pointer column, "N marked" by the filter) and moves down, so Space no longer types into the filter; with marks Enter opens all of them (folders in the picked opener, else their own) and ^d deletes all in one save (one ^z or `upex undo` restores them); Settings > Enter (`upex config set enter stay`) keeps the selector open after Enter (opens in place, also workspaces, scripts and marked rows); Settings > Tabs (`upex config set views no-workspaces|no-apps|shortcuts`) hides tabs here and in upex ui, a hidden start view opens Shortcuts; ^a/^e/^r/^d add, edit path, rename, delete with a green confirmation; ^p pins or unpins the selected shortcut, ^x archives it after y / n (^z undo), Alt+↑↓ moves a pinned one among the pinned (saved as pinOrder, upex ui follows it); ^y copies the selected path (the opener row has no Copy entry, `upex <name> copy` still works); Settings > Max rows (Auto/8/12/16, `upex config set maxRows 12`) sets the list height, Auto (default) fills the screen in full screen and keeps 8 inline (inline, Settings hides Auto and its "8" keeps auto); in full screen the key rows sit at the bottom and a terminal 140+ columns wide shows a detail pane of the selected row (full path, its note from `upex note` (wrapped, 3 lines at most), other shortcuts on the same path in yellow, opener, aliases, tags, opened count, a stale hint when not opened in 30+ days (a click on it asks to archive), added, expiry; workspace entries; with marks, every marked row with what Enter opens it in and what ^d does) right of the list; narrower (60+), Shift+→ opens it anyway and Shift+← or Esc closes it, or Settings > Detail pane > Narrow screens Always (`upex config set narrowPane always`) always shows it; Settings > Detail pane > Width (`upex config set paneWidth narrow|wide`, normal by default) sets its share of the screen; Settings > Detail pane > Open goals (`upex config set goals 3|5|10`, off by default) adds a folder's upgo goal progress (a done/total bar, dropped goals left out), its open goal count and that many open goals from its goals.json (grouped under their phase), Shift+→ picks one there (↑↓ or wheel) and Enter copies "id: title" plus its body, a click on a goal copies it right away and a click on the pane's path copies the path; Settings > Detail pane > Git status (`upex config set git on`, off by default) adds a folder's branch, ahead/behind, changed file count with lines added (green +N) and deleted (red -N), and last commit (looked up in the background, cached a few seconds) and its origin web page, ^g or a click opens that page in the browser; Settings > Recent on top (`upex config set recentStrip on`, off by default) shows the last 3 opened above the list under a Recent heading; ^e/^r start filled with the current path/name, the line edits like a shell (←→ cursor, ^←→ word, Home/End, ^⌫ or ^w deletes a word, Del), ^u clears it, an empty path = cwd; ^⌫ also works in the filter; green confirmations fade after 3s; with Terminals = Tabs in Windows Terminal, opening a terminal (or a command-line shortcut) keeps the selector open and opens the tab beside it; Enter on a shortcut whose folder is missing stays open with "path missing, ^e to fix"; ^s on a folder shortcut lists its package.json scripts (in the detail pane when it shows, the list stays; else in place of the list), ↑↓, wheel or a click pick one, Enter or a double-click runs it in a terminal like `upex run`, Esc or ← goes back; long names clip with …; ^z undoes the last delete of the session unless the name was taken since; ^u in browse mode starts `upex ui` inside the selector, opens the browser and shows "upex ui running <link>"; ^u again or closing the selector stops it) or `upex ui` (starts a server, opens a browser). Use a name or sub-command.
- Find a project path: `upex go <name>` prints only the raw path (exit 1 if unknown). `upex go web/src` resolves a subpath. `upex ls` shows the full live table, `upex ls <tag>` filters. Fuzzy matching and aliases apply; trust the printed path.
- Opening things spawns windows on her desktop: do it only when she asks. If the target is unambiguous (one plausible match, or the current repo), just run it, don't ask.
- New names can't contain spaces; older ones can (e.g. `"Led start"`): quote them.
- Prefer `rm --archive` over a hard delete unless she says delete.
- `upex stale` without `--yes` only lists when not in a TTY (safe to run); `--yes` archives every listed shortcut, so only use it when she asks.
- `--ttl` shortcuts are archived automatically once expired (by the next command other than `go` and the hidden ones, notice on stderr; `go` already refuses them); `upex restore` brings one back permanently.
- Never edit `~/.upex/*.json` by hand; use the commands below.
- To change a setting (terminalLayout, sort, defaultOpener, appearance: theme, accent, density, paths, ...) use `upex config set <setting> <value>`, never edit config.json by hand; `upex config get <setting>` prints just the value; `upex config reset [setting]` puts one (or all) back to the default (upex ui Settings has a Reset per section). accent also takes a hex color (`upex config set accent ff66aa`, the # is optional since shells read it as a comment). sort: `recent` (most used), `name`, `opened` (last opened), `added` (recently added). startView `last` reopens the tab (and in the selector the picked opener) the selector or upex ui was left on. rowDetails: `both`, `tags`, `badges` (★ = pinned, app, missing), `none` (selector, ls, upex ui; piped ls keeps both). pinned: `top` or `section` (Pinned / All headings in the selector and upex ui). views: `all`, `no-workspaces`, `no-apps`, `shortcuts` (tabs shown in the selector and upex ui). enter: `quit` or `stay` (selector only).
- "What do I use most?" questions: `upex stats` (read-only, safe to run). Every open is logged with its opener (`cd` for go, `app`, `url`, `web`, or the opener key); counting started when the log was added, so older use shows only in the all-time column.

## Commands

| Command | Does |
|---|---|
| `upex <name> [app] [count]` | Open a shortcut. app: `explorer` (default, or the shortcut's own opener), `vscode`, `cmd`, `claude`, `webstorm`, or a custom opener |
| `upex go <name>` | Print path |
| `upex ls [tag] [--git] [--archived]` | List shortcuts |
| `upex add [name] [target] [--app\|--cmd\|--url] [--tag a,b] [--opener <app>] [--alias a,b] [--ttl 7d]` | Register a folder (default cwd), app, command line or URL; no name or `.` names a folder after itself (spaces as dashes); `--ttl` (`30m`/`12h`/`7d`/`2w`) makes it temporary |
| `upex edit <name> [target] [--opener <app>\|--no-opener]` / `rename <old> <new>` | Change, rename |
| `upex rm <name> [--archive]` / `restore <name>` | Delete, or archive (hidden, restorable) |
| `upex pin [name]` / `unpin <name>` | Pin to the top of the selector and `upex ui` (no name: list pinned) |
| `upex undo` | Roll shortcuts back to before the last change (from `~/.upex/backups`, up to 10 steps; keeps usage stats; not workspaces/config; no redo, so only when asked) |
| `upex tag [name] [tags...] [--remove] [--clear]` | Manage tags; `upex open <tag>` opens all tagged |
| `upex note <name> [text...] [--clear]` | Short free-text note on a shortcut, shown in the selector's detail pane (no text: print it) |
| `upex alias [name] [aliases...] [--remove] [--clear]` | Extra names for a shortcut |
| `upex cmd <name> [count] [start...]` | Open N terminals there, optionally running a command |
| `upex run <name> [script]` | Run a package.json script in a terminal |
| `upex web <name>` | Open the project's git remote page (GitHub etc.) |
| `upex ws ...` | Workspaces (`ws add`, `ws rm`, `ws <name>`) |
| `upex app [alias] [command] [--remove]` | Custom openers (also on the `upex ui` Settings tab: add, change command, delete) |
| `upex stats [--days N] [--all]` | Most used shortcuts and openers (default last 30 days) plus opens per week, from `~/.upex/history.jsonl` |
| `upex config` / `config get <setting>` / `config set <setting> <value>` / `config reset [setting]` | List settings with their options, print one, change one (same as the Settings tabs), or reset one or all to defaults |
| `upex stale [days] [--yes]` | Shortcuts not opened in N days (default 60), never-opened first; offers to archive each |
| `upex check [--prune]` / `doctor` | Report (or prune) broken paths / check store, openers, shell setup |
| `upex copy <name>` / `last` / `export [file]` / `import <file> [--replace]` | Misc |

`upex help` and `upex <command> --help` are authoritative if this table drifts.
