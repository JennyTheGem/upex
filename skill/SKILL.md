# upex

Jenny's CLI for named shortcuts to folders, apps, command lines and URLs. Data: `~/.upex/links.json` + `config.json`. Source: `E:\Downloads\Projects\Assets\upex`. If `upex` is not on PATH, use `node E:/Downloads/Projects/Assets/upex/bin/upex.js`.

## Rules

- Never run bare `upex` (interactive selector, takes over stdin and by default the whole terminal with mouse support: click a row to select, click it again or double-click to open, right-click a row for a menu (open in each opener, edit, pin, copy path, archive; workspaces: open all, edit, delete), click tabs / openers / settings options, wheel moves the selection; PgUp/PgDn move a screen of rows, Home/End the first/last (every tab, Settings too); Settings > General > Number keys (`upex config set numberKeys on`, off by default) numbers the first 9 visible rows in the pointer column and 1 to 9 opens that row right away (Shortcuts, Apps, Workspaces; with an empty filter, else the digit types; Alt+1 to 9 also with a filter); with no shortcuts yet it still opens (on Shortcuts, ^a adds the first; piped/non-TTY it prints "No shortcuts saved"); Settings > Full screen Off draws it inline without mouse; Settings > Mouse Off (`upex config set mouse off`) keeps full screen but leaves text selection to the terminal; Settings > Stale after (`staleAfter` 30/60/90/180, default 60) sets the days for is:stale, Maintenance > Stale and `upex stale`; Settings > Key hints Short (default) shows one row of what the picked row can do now (open, opener, mark or with marks ^x archive, edit, Esc only when it does more than quit, details or goals) with `? all keys` (`^k all keys` while filtering) at its right end, Full (`upex config set keyHints full`) every key wrapped onto more rows, Off none; a key hint shows the key dim and its word plain; `?` on an empty filter (or ^k) shows every key over the list in any Key hints mode (any key or a click closes it, `?` with a filter typed types); Settings > Glyphs ASCII (`upex config set glyphs ascii`) draws the selector with plain ASCII (< > | - . ^ v *) for fonts that show boxes; Esc clears a typed filter, then the marks, then closes a Shift+→ detail pane, then quits; typing `#vel` in the filter keeps shortcuts with a tag starting with vel (Space marks, so chain them: `#vel#web` needs both tags, `api#vel` also searches api fuzzy); `@vs` keeps folders whose default opener starts with vs (vscode), `is:pinned`, `is:missing`, `is:stale` (staleAfter days, 60 by default), `is:app`, `is:new` (added in 7 days) and `is:temp` (has a --ttl expiry) narrow the same way (prefix, `is:p`; an unknown is: matches none), also in the upex ui search; a row the filter hit through an alias, not its name, shows a dim `via <alias>`; a --ttl shortcut shows a dim `2d left` badge (also in upex ls); with no matches, Enter or a click on `add "<text>" here` adds the typed text as a folder shortcut on the cwd and opens the edit form (Shortcuts tab, no #@is: tokens; a bad name stays in the prompt to fix), ↑↓ picks `search archived` (when archived ones have the text in name or path), which opens Settings filtered to them; Space marks (again: unmarks) the highlighted row (Shortcuts/Apps, ● in the pointer column, "N marked" by the filter) and moves down, so Space no longer types into the filter; with marks Enter opens all of them (folders in the picked opener, else their own; ^u again or closing the selector stops it) or `upex ui` (starts a server, opens a browser; there Enter in the search opens the top row, ↓ moves into the list, ↑↓ Home End move between rows, on a row Enter opens, e or F2 edits, p pins, Del archives; each row shows Open plus a More menu (open with, pin, copy, edit, its package.json scripts (each runs in a terminal like `upex run`), archive, delete); the goals setting (`upex config set goals 3|5|10`, shared with the selector's detail pane) adds a folder's upgo progress (done/total) and that many open goals on one line under its name; Settings has Backup (Download bundle like `upex export`, Import bundle merges like `upex import` with counts and one Undo for the shortcuts) and Insights (read only: top shortcuts of 30 days, openers and opens per week like `upex stats`, and the `upex doctor` checks with Run again); removing a workspace's last entry asks first, and deleting a workspace, workspace entry or custom opener gets an Undo in the toast). Use a name or sub-command.
- An open selector reloads by itself when links.json or config.json changes, so your CLI edits show up there without a restart.
- Find a project path: `upex go <name>` prints only the raw path (exit 1 if unknown); `upex go --json <name>` prints `{ "name", "path" }` or `{ "error" }` (exit 1). `upex go web/src` resolves a subpath. `upex ls` shows the full live table, `upex ls <tag>` filters. Fuzzy matching (setting `fuzzy`) and aliases apply; trust the printed path.
- Machine-readable: `--json` on `upex ls` (`[{ name, ...entry, exists }]`), `go` (put it before the name; after the name works only without a cd wrapper), `tag` (`{ tag: count }`, or `{ name, tags }` for a shortcut) and `doctor` (`[{ status, check, detail }]`, exit 1 on a fail). Prefer it over parsing tables.
- `--dry-run` anywhere on an open line (`upex web code --dry-run`, `cmd`, `run`, `ws`, `open <tag>`, `cd <path> <opener>`, `copy`) prints each command upex would spawn (with `(in <cwd>)`) and ends with "dry run, nothing ran" on stderr; nothing launches and no shortcut, setting or use is saved (on any command). After `go <name>` it belongs to the command; before `go` it prints that command instead.
- Opening things spawns windows on her desktop: do it only when she asks. If the target is unambiguous (one plausible match, or the current repo), just run it, don't ask.
- New names can't contain spaces; older ones can (e.g. `"Led start"`): quote them.
- Prefer `rm --archive` over a hard delete unless she says delete.
- `upex stale` without `--yes` only lists when not in a TTY (safe to run); `--yes` archives every listed shortcut, so only use it when she asks.
- `--ttl` shortcuts are archived automatically once expired (by the next command other than `go` and the hidden ones, notice on stderr; `go` already refuses them); `upex restore` brings one back permanently.
- Never edit `~/.upex/*.json` by hand; use the commands below.
- To change a setting (terminalLayout, sort, defaultOpener, appearance: theme, accent, density, paths, ...) use `upex config set <setting> <value>`, never edit config.json by hand; `upex config get <setting>` prints just the value; `upex config reset [setting]` puts one (or all) back to the default (upex ui Settings has a Reset per section). accent also takes a hex color (`upex config set accent ff66aa`, the # is optional since shells read it as a comment). sort: `recent` (most used), `name`, `opened` (last opened), `added` (recently added). startView `last` reopens the tab (and in the selector the picked opener) the selector or upex ui was left on. rowDetails: `both`, `tags`, `badges` (★ = pinned, app, missing), `none` (selector, ls, upex ui; piped ls keeps both). usage: `off` (default), `ago` (last opened like 3d ago) or `opens` (open count), at the right edge of a row in the selector and upex ui. pinned: `top` or `section` (Pinned / All headings in the selector and upex ui). groups: `off` or `tags` (pinned ones under Pinned on top, then a #tag heading with its count per tag, like folders, in the sort order (A to Z for sort name), rows inside it sorted too; a shortcut with two tags shows under both, pinned ones also in their tag (★), untagged last; selector and upex ui, not while searching). views: `all`, `no-workspaces`, `no-apps`, `shortcuts` (tabs shown in the selector and upex ui). enter: `quit` or `stay` (selector only). fuzzy: `normal`, `exact` (the typed letters in a row, no typos) or `loose` (more typos), for the selector filter and name resolution (`upex <name>`, `go`). searchIn: `all` (names, aliases, paths, tags) or `names` (names and aliases; selector filter and upex ui search; `#tag`, `@opener` and `is:` tokens still filter). flash: `3`, `6` or `key` (how long the selector success message stays). updateCheck: `on` (default) or `off` (daily background npm check, one dim "update available x -> y" line on stderr after a command when a newer upex is out, terminals only; never for go, __resolve, __names, completion or the selector; the selector shows the version dim at the right end of its bottom rule, always on Settings, elsewhere from 100 columns; upex ui shows it at the foot of its sidebar, and with a newer one out the npm i -g command, a click copies it). terminalLayout: `here` (default: one terminal opener runs in the current terminal, upex quits and a shell starts at the folder, `exit` comes back; several at once, workspaces, upex ui and non-TTY callers like you get separate windows), `windows`, and on Windows `tabs` / `panes`; paneSplit and terminalShell are Windows only.
- Openers that aren't installed (WebStorm, VS Code, Claude, a Linux terminal) are hidden from the opener row on every system; custom openers always show. Linux terminals: `$TERMINAL`, the desktop's own, `x-terminal-emulator`, then gnome-terminal, konsole, xterm and others.
- "What do I use most?" questions: `upex stats` (read-only, safe to run). Every open is logged with its opener (`cd` for go, `app`, `url`, `web`, or the opener key); counting started when the log was added, so older use shows only in the all-time column.

## Commands

| Command | Does |
|---|---|
| `upex <name> [app] [count] [--dry-run]` | Open a shortcut (`--dry-run`: print the command instead). app: `explorer` (default, or the shortcut's own opener), `vscode`, `cmd`, `claude`, `webstorm`, or a custom opener |
| `upex go [--json] <name>` | Print path (`--json`: `{ name, path }`) |
| `upex cd <path> [opener] [count]` | Print a folder (an existing path, `~` ok, else a shortcut, else a learned folder, see `upex learned`; a file gives its folder). Jenny's shell wrapper cds there; with an opener it then opens it there like `upex <name> <opener>`. Without a wrapper an opener just opens the path |
| `upex learned [--clear]` | Folders learned from `upex cd <path>` (each one counts a visit; home and drive roots don't) that have no shortcut yet, most used first, with visits and last visit. `upex cd <name>` jumps to the most used one whose folder name contains `<name>` (an exact name first) when no path or shortcut matches. From 3 visits the selector offers the top one as a plain `+ name  path  you cd here often` row on top of the Shortcuts list, a blank row under it (`^n` or a click adds it: name prompt prefilled, then the edit form; `^l` stops offering it) and `upex ui` shows a dashed "You cd into X often" strip over the Shortcuts list (Add shortcut fills the add form, Dismiss has Undo). `--clear` forgets them all. Data: `~/.upex/visits.json` (300 kept) |
| `upex pick` | The selector drawn on stderr; Enter prints the chosen path to stdout (marked rows or a workspace: one per line; url or app command when no folder), Esc prints nothing and exits 1. Needs a terminal, so not for you: Jenny runs it as `cd "$(upex pick)"` or `upex pick \| clip` |
| `upex ls [tag] [--git] [--archived] [--json]` | List shortcuts |
| `upex add [name] [target] [--app\|--cmd\|--url] [--tag a,b] [--opener <app>] [--alias a,b] [--ttl 7d]` | Register a folder (default cwd), app, command line or URL; no name or `.` names a folder after itself (spaces as dashes); `--ttl` (`30m`/`12h`/`7d`/`2w`) makes it temporary |
| `upex edit <name> [target] [--opener <app>\|--no-opener]` / `rename <old> <new>` | Change, rename |
| `upex rm <name> [--archive]` / `restore <name>` | Delete, or archive (hidden, restorable) |
| `upex pin [name]` / `unpin <name>` | Pin to the top of the selector and `upex ui` (no name: list pinned) |
| `upex undo` | Roll shortcuts back to before the last change (from `~/.upex/backups`, up to 10 steps; keeps usage stats; not workspaces/config; no redo, so only when asked; upex ui shows an Undo button in the toast after a delete, archive or prune; its workspace and opener deletes undo on their own) |
| `upex tag [name] [tags...] [--remove] [--clear] [--json]` | Manage tags; `upex open <tag>` opens all tagged |
| `upex color <name> [value] [--clear]` | Color label on a shortcut: red, orange, yellow, green, blue, purple, gray, #rrggbb (the # optional) or one emoji; a dot (or the emoji) before the name in the selector and upex ui (editable in both edit forms; no value: print it; `none` or --clear removes it) |
| `upex note <name> [text...] [--clear]` | Short free-text note on a shortcut, shown in the selector's detail pane and under the name in `upex ui` (editable in both edit forms; no text: print it) |
| `upex alias [name] [aliases...] [--remove] [--clear]` | Extra names for a shortcut |
| `upex cmd <name> [count] [start...]` | Open N terminals there, optionally running a command |
| `upex run <name> [script]` | Run a package.json script in a terminal (also in the `upex ui` row More menu) |
| `upex web <name>` | Open the project's git remote page (GitHub etc.) |
| `upex ws ...` | Workspaces (`ws add`, `ws rm`, `ws <name>`) |
| `upex app [alias] [command] [--remove]` | Custom openers (also on the `upex ui` Settings tab: add, change command, delete) |
| `upex stats [--days N] [--all]` | Most used shortcuts and openers (default last 30 days) plus opens per week, from `~/.upex/history.jsonl` |
| `upex config` / `config get <setting>` / `config set <setting> <value>` / `config reset [setting]` | List settings with their options, print one, change one (same as the Settings tabs), or reset one or all to defaults |
| `upex stale [days] [--yes]` | Shortcuts not opened in N days (default: `staleAfter` setting, 60), never-opened first; offers to archive each |
| `upex check [--prune]` / `doctor [--json]` | Report (or prune) broken paths / check store, bad links.json entries (wrong field types are coerced or dropped, an entry with no path/app/url is skipped but kept in the file; any command warns once on stderr), openers, shell setup |
| `upex setup [bash\|zsh\|fish\|cmd]` | No arg: how to set up cd support. `bash`/`zsh` add an upex block to ~/.bashrc / ~/.zshrc (rerun updates it), `fish` writes functions/upex.fish, `cmd` the cmd.exe wrapper |
| `upex copy <name>` / `last` / `export [file]` / `import <file> [--replace]` | Misc |

`upex help` and `upex <command> --help` are authoritative if this table drifts.
